## Why

竞赛主办方需要将现有英文问卷可靠地搬到线上，在无需自行运维服务器的前提下收集结构化答案和开放式反馈。主办方还需要仅限内部访问、容易理解的统计结果，避免手工合并每份答卷。

初稿包含 34 道候选题目（源文档本身标题为 `Potential Questions`），完整填完的负担偏重，在手机端尤其明显。主办方希望先按重要程度筛选并精简题目，再把问卷拆分为短页，让手机端和电脑端使用同一份问卷流程。

## What Changes

- 将答题进度条移至答题卡顶部，让窄屏上的目录位于进度条之前，进度紧邻当前题目。

- 新增公开的纯英文在线问卷，按清晰的章节结构展示经重要程度筛选后的 23 道题目（原始候选 34 道）。
- 将每个章节拆分为短页：每页最多 2 道选择类题目（单选、多选、评分），开放文本题目每题独占一页；手机端与电脑端使用同一题目顺序和同一分页规则。
- 在问卷页面显示问题联系信息：`Questions? Contact Dr. Song at hui.song@rmit.edu.au.`。
- 使用填写者姓名和单位标识答卷，使同一填写者能够重新载入并修改最新答卷。
- 执行已确认的必填、选填、条件题和 `Other` 补充说明验证规则。
- 通过受控数据库操作将答卷保存到 Supabase，并使用 GitHub Pages 托管静态客户端。
- 新增仅限主办方访问的纯英文管理后台，包含一个预先创建的管理员账号、总体指标、选择题分布、带署名的开放回答、填写者详情、搜索/筛选和 CSV 导出。
- 在管理后台新增答卷回收站：管理员可以将答卷移入回收站、恢复答卷，或在输入填写者姓名确认后永久删除。回收站记录不进入总体指标、选择题分布、开放回答、正常填写者列表或 CSV 导出。
- 被移入回收站的身份在公开问卷中视为不存在；同一姓名和单位重新提交时，系统重新激活该记录并以新答案替换原回收站答案。
- 新增可靠提交、本地草稿恢复、防止重复提交和并发编辑冲突检测。

## Capabilities

### New Capabilities

- `competition-organizer-survey`：公开的填写者身份识别、精简后的分章节分页问卷、联系信息、验证、答卷创建、重新载入和修改行为。
- `private-survey-analytics`：管理员身份验证、受保护的答卷访问、总体指标与图表、带署名的开放回答查看、筛选、CSV 导出，以及答卷的软删除、恢复和永久删除生命周期。

### Modified Capabilities

- 无。

## Impact

- 引入一个全新的静态 Web 应用，包括公开问卷和私有管理界面。
- 引入 Supabase Auth、PostgreSQL 存储、行级安全策略和受控数据库函数。
- 为答卷引入删除状态与删除操作者审计字段，并增加仅允许白名单管理员调用的软删除、恢复、永久删除和回收站读取函数。
- 引入浏览器端图表渲染和 CSV 生成。
- 题目由 34 道精简为 23 道，显示编号随之重排为 1 至 23；稳定的内部题目 id 保持不变，已保存答卷中的历史答案继续留在数据库中。
- 已移除题目不再出现在问卷、统计、开放回答编号和 CSV 导出列中；其历史答案只能通过数据库直接查询。
- 正式上线前需要准备一个 Supabase 项目、一个管理员账号和 GitHub Pages 部署配置。
- 接受已记录的隐私限制：只要准确知道填写者的姓名和单位，就能够重新载入并修改其答卷。
